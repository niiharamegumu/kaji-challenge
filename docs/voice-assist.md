# 常駐音声アシスト

## 利用範囲

「塩は購入した、レモンを追加して」のように、1回の送信で複数種類の操作をまとめて依頼できる。含まれる操作を順序通り処理し、完了と追加など各結果を個別に表示する。最大10操作、指定するToDo名・追加項目は合計50件まで。追加先などに確認が必要な場合は、完了を含む全操作を保留し、回答後にまとめて実行する。途中の保存エラーでは全体を戻す。未対応の操作を含む場合も一部だけ実行しない。

ヘッダーの「？」から、対応する操作と短い指示例を確認できる。現在はToDoに対応し、追加・カテゴリー/名前検索・完了・削除を扱う。「ToDoに〜追加」のような明示的な種類の指示と自然な買い物表現をintentで区別する。ほかの機能は今後の拡張対象とし、未対応操作を実行しない。画面は見出し・本文・入力欄の余白を抑え、主要ボタン44pxと入力文字16pxを保持する。

通常停止後の文字起こし中は入力欄に回転するアイコンを表示し、二重操作を抑止する。「停止して送信」はタップ直後、音声の停止応答や文字起こしを待たずに、会話欄へ音声アイコンの仮メッセージと処理中のドットを表示する。送信ボタンも回転アイコンへ切り替え、文字起こし後に仮メッセージを認識した全文へ置き換える。ToDo操作の完了は実応答後に表示する。「文字にしています」「音声を受け付けました」などの状態文言は読み上げ専用とし、画面には表示しない。失敗や確認欄への戻しでは仮表示を消し、元の下書きを保持する。端末の「動きを減らす」設定ではアイコンを静止する。

表示用stateを更新した後は、直ちに専用Web WorkerへWAV/base64変換を渡す。完了を非同期で待ち、その間にブラウザーが画面の待機アイコンを描画できるようにする。文字の送信も状態更新後にHTTP要求を開始し、非同期の完了を待つ。frame数や固定時間による描画待ちは挟まない。実際のタップ反応の検証にはネットワーク待機だけでなく、変換にCPU負荷を入れたテストを使う。

下部のガラス調の波形ボタンで、入力欄のあるアシスタント画面を開く。開くだけではマイクを要求せず、テキストだけでも送信できる。録音ボタンを押すと、そのボタンを直ちに回転アイコンへ切り替えて準備中を示す。実際の録音開始応答を受けてから録音中の表示へ進み、もう一度押すと停止する。発話の間や無音で自動終了しない。

- **停止**: 録音を止めて文字起こしし、入力欄へ反映する。すでに入力した文章があれば改行して追記し、確認・修正してから送信する。
- **停止して送信**: 明示操作を記録し、停止・文字起こし後に1回だけ送信して実行する。途中で閉じる/失敗した場合は送信しない。
- **2分上限**: 録音データを制限するため停止して文字起こしし、確認欄へ戻る。自動送信しない。2,000文字を超えた追記結果も切り捨てず、編集後の送信を促す。

返事は文字で表示する。画面は暖かい単色背景・余白・入力欄・少数のアイコンを基本とし、大きな発光オーブや自動読み上げは使わない。[ChatGPTの音声入力](https://help.openai.com/en/articles/12168547-voice-dictation-faq)と[入力欄のデザイン](https://chatgpt.com/features/voice/)を参考に、アプリ既存の配色・フォントへ合わせる。起動ボタンは引き続き「その他」と同じ62pxのガラス調。

録音・文字起こし・実行は同時に重ねない。画面の非表示、ページ移動、ログアウト、所属変更では終了し、マイク・通信・会話と未送信の文字を破棄する。閉じた後や画面復帰だけで録音を再開しない。

| 発話 | 動作 |
| --- | --- |
| 買い物に牛乳を追加して | 実在する「買い物」に1件追加 |
| ToDoに牛乳を追加して | 登録済みカテゴリーから内容に合う追加先を推測。不明なら聞き返す。登録カテゴリーがなければ未分類 |
| 買い物（聞き返しへの返事） | 未確定の名前と組み合わせて検証・追加 |
| やることを教えて／買い物リストを教えて | 実データの件数と先頭2件を要約し、最大20件を表示 |
| 牛乳を探して／買い物の牛乳を探して | 名前の部分一致、またはカテゴリーとの組み合わせで検索 |
| 牛乳を買った／牛乳と卵を完了して | 名前が完全一致するToDoをすべて完了。カテゴリー指定時はその中だけ |
| 買い物の卵を削除して | 指定カテゴリー内の同名ToDoをすべて削除 |
| 塩は購入した、レモンを追加して | 塩を全件完了し、レモンを追加する。両方の結果を表示 |
| 牛乳と卵を追加して | 複数品をまとめて追加。カテゴリー不明なら全件保留して聞き返す |
| やめて（聞き返し中） | 未確定の内容を破棄 |

編集・期日・リマインダー・日間/週間タスク・汎用会話は対象外。追加先は実在するカテゴリー名と内容から推測し、不明な場合は確認する。検索・完了・削除のカテゴリーは明示指定だけを使い、推測で対象を変えない。検索は名前の部分一致、完了・削除は名前の完全一致で扱い、NFKC・前後空白・英字大小を正規化する。完了は既存画面と同じ物理削除で履歴を残さない。名前を指定しない全件削除には対応しない。音声解釈は確率的なので、実AIでの誤認識評価が必要。

検索結果が20件を超える場合は、一覧の先頭に「全○件のうち先頭20件を表示しています。続きはToDo画面で確認してください」と表示する。件数は一致した全件分で、アシスト内での追加ページ取得は行わない。

既存の「追加」フォームと同時に起動しない。カレンダーは「その他」へ移動し、URL `/calendar`、ホームのリマインダー、予定データ、Cronは維持する。`/assist` は作らない。

## 実装と境界

- `features/assist` がマイク・手動録音・直近の会話・ダイアログを管理する。RootLayoutは本人/所属をkeyにして状態を破棄する。native dialogで背面操作とフォーカス移動を制限する。
- AudioWorkletで実sampleRateのPCMを取得し、専用の`audio-encode.worker.ts`でmono/16kHz/16bit WAVとbase64へ変換する。PCMのArrayBufferを転送してコピーを避け、Workerから音声を外部送信・保存しない。変換成功・エラー・10秒期限・画面終了ではterminateする。同期変換のfallbackは使わない。無音や間を含めて手動停止まで保持し、最大2分に制限する。短いクリック音とデジタル無音だけではASRを呼ばない。録音開始中は「準備中」と表示し、workletが最初の入力を処理したstarted応答を受けてから「録音中」に進む。開始応答は5秒で打ち切る。開始要求の重複では録音済みPCMをリセットしない。
- 停止時はworkletへfinishを送り、最後の1024sample未満のPCMとfinished応答を順に受け取ってからWAV化する。workletが取り込んだ総sample数と受信した総sample数を照合する。2分上限でWAV化の対象から外れるPCMも受信数には含める。不一致や1.5秒以内に応答しない場合はエラーとし、不完全な録音をASRや自動送信に渡さない。この照合はマイクの準備前の発話や端末側の入力欠落を検出するものではない。
- マイク初期化中はlive trackを維持し、聞き取り開始前のPCMはworkletから送らない。停止時にtracks/AudioContextを解放し、文字起こし・文字確認・LLM実行中は保持しない。遅い許可・ASR応答・停止して送信の意図は世代番号で無効化する。ASR失敗時も元の入力は残す。
- 起動時のマイク許可待ちは20秒、AudioContext再開とAudioWorklet準備は1回5秒で打ち切る。明示的な録音操作内でWorkletの静的module読み込みとマイク許可待ちを並行して開始し、許可後に同じmoduleの完了を待って接続する。読み込みが先に失敗しても未処理のPromise拒否にせず、取得済みのマイクを使ってAudioContextを1回だけ作り直す。許可拒否・許可待ちの期限超過ではマイクを再要求しない。復旧できなければ録音を解放し、閉じてもう一度開く案内を表示する。終了後に許可・module読み込みが完了しても録音を再開しない。
- 許可取得後はマイクをgain=0の無音グラフへ先に接続してからAudioContextのresumeを待つ。再開完了後に入力を接続する順序で、入力を必要とする初期状態が5秒の復旧待ちへ入ることを避ける。Worklet準備後に無音グラフの入力先をWorkletへ付け替える。マイク要求や最初のresumeは引き続きボタンのgesture内で実行する。この順序のテスト成功を、iPhone実機の待ち時間の解消確認とは扱わない。
- 録音開始はボタン操作に限定する。起動全体の30秒期限を設け、待ち続けず再録音または終了に進める。聞き取り中の中断、画面非表示・ページ離脱では停止する。マイク要求は明示的な録音開始につき1回で、復旧時は再要求しない。
- マイク許可の保持はOS/ブラウザー管理であり、PWAの終了後も許可を保存することをアプリから強制できない。許可されたように見せるlocalStorageフラグや、閉じた後のマイク保持は使わない。毎回確認される場合は端末・ブラウザーのマイク設定を確認する。Safariとホーム画面PWAの権限状態はそれぞれ実機で確かめる（[getUserMediaの許可仕様](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)）。
- 返事は画面へ表示し、SpeechSynthesisや端末内の日本語音声の有無を入力・実行の条件にしない。VisualViewportの高さとoffsetに合わせ、キーボード表示時も入力欄と送信操作が隠れにくいレイアウトにする。実機のキーボード挙動は別途確認する。
- `POST /api/assist/transcribe` は音声とexpectedTeamIdだけを受け、Whisperの文字起こしだけを返す。本文は6 MiB以下、実WAVの長さ・形式・無音を検証する。`POST /api/assist/turn` はユーザーが送信した文字とexpectedTeamId・任意のdraftだけを受け、Gemmaの解釈と認可済みToDo操作を実行する。こちらの本文上限は1 MiB。実行入口は音声だけの旧入力を拒否する。
- 両入口はstrict Zod契約、same-origin、Better Auth、DB上のセッション・所属、本人ごとの頻度制限を通す。AI待機前に所属を固定し、各待機後と業務操作前後にも再検査する。ASRも送信もそれぞれ予算を予約する。通常の停止・上限停止からはLLMやDB更新を呼ばず、「停止して送信」が明示された場合だけASR後に続けて実行する。
- `AssistAi` portの実装だけがWorkers AIに依存する。Whisper large v3 turboへbase64 WAVと`language:"ja"`・`task:"transcribe"`を渡して日本語文字起こし、Gemma 4 26B A4Bで限定intentのJSONを取得する。Gemmaはthinkingを無効化し、名前付きJSON schemaで出力を指定する。成功する指示は単独操作でも必ず操作配列として返し、購入済みの句は追加対象から外すと同時に完了操作として保持する。未知キー・任意ID・対象外操作・途切れたJSONは拒否する。登録済みカテゴリー名は意味から追加先を選ぶために渡すが、ToDo一覧の内容はLLMへ送らない。
- 追加は認可済みRepositoryのatomic複数保存、一覧/検索は既存 `executeOperation` を使う。完了・削除は名前集合に対する単一の認可付きSQLで行い、同名の全件を処理する。全項目を検証してから保存し、一部だけ追加しない。JSON出力とdraftの上限は50項目。50の異なるカテゴリーでもD1のbind数上限を越えないよう、カテゴリー参照をJSON配列でまとめてSQL検査する。返事は保存/取得結果と実際の削除件数から定型生成する。migration `0010_assist_usage.sql` は利用量カウンターのみを追加する。
- 未確定draftは最大2分、名前/カテゴリー/不足情報/期限と、複合指示の場合は保留中の操作配列を保持する。本人や権限の根拠にせず、毎回再検証する。会話はパネル内メモリーのみで、閉じると破棄する。
- 更新は自動再送しない。中断や応答不明では既に保存されている可能性を表示して一覧を再取得する。処理中に閉じた場合は通常画面の通知で保存済みの可能性を伝える。成功時は既存ToDo queryとRealtimeで反映する。

## 設定・費用

**実推論と配備は既定で無効。作業担当者は、有料になり得る実AI試験・Cloudflareへの変更の前に、目的・回数/費用の見込みをユーザーへ連絡する。** この初版の自動検証は実AIを呼ばない。

| 設定 | 初期値・意味 |
| --- | --- |
| `ASSIST_ENABLED` | `false`。有効化は明示的に `true`。AIより前に停止する |
| `ASSIST_GATEWAY_ID` | `kaji-voice`。AlchemyとWranglerで一致 |
| `AI` | 既存アプリWorkerのみ。Viteのdev/build/previewではbindingを除去し、remoteBindingsもfalse |
| `ASSIST_LIMITER` | 本人ごと12要求/60秒。ASR・送信・聞き返しをそれぞれ数える。分散環境での厳密な全世界カウンターではない |
| Gateway | ログなし、キャッシュなし、24推論/60秒。ASR・送信はそれぞれ最大1推論 |
| Gateway認証 | Alchemyで `authentication:true` を明示。未認証HTTPを拒否し、同一アカウントのWorker bindingは自動認証する。特定Workerだけのallowlistではなく、有効なAPI token経由も許可される |
| Spend limits | $1/1日・$5/30日。`limit` は米ドル単位で `1` / `5` を指定する。厳密な請求上限ではない |
| D1利用上限 | アプリ全体12要求/60秒、50要求/UTC日、試用累計500要求。ASRと送信は別々に消費する。AIより前に条件付きUPDATEで予約。失敗・中断も消費、日付変更や再配備で累計を戻さない |
| 推論上限 | 音声120秒、文字2,000文字、解釈入力JSON 65,536 UTF-8 bytes、出力8,192 tokens/65,536 bytes。別モデルへの自動切替なし |
| 待機・録音 | 入力待ちは自動終了しない。録音は最大2分。再録音には本人のタップが必要 |

本番はGitHub Environmentの `ASSIST_ENABLED` をCDが読む。Alchemyは有効時に専用Gatewayを宣言し、無効化時はretainして既存資源を削除しない。モデル名・Gateway・RateLimitはMCP Workerに追加しない。配備はこの実装だけでは行わない。

Gateway認証の設定変更は次の有効状態でのAlchemy配備で反映する。手動でスイッチだけ変更しても、IaCが未変更なら次回配備で戻るため、`authentication:true` を正本とする。AI Binding経由では追加のGateway tokenやブラウザー側の秘密情報は不要（[Cloudflare公式](https://developers.cloudflare.com/ai-gateway/configuration/authentication/)）。本番の反映確認と実推論の疎通は別の検証であり、ローカルテスト成功だけで完了扱いにしない。

ローカルのWrangler宣言は生成型のためにAIを含むが、通常の起動は `bun run dev` / `bun run preview` を使い、ViteでAIを除去する。`wrangler dev` の直接実行はリモートAIへ接続し得るので通常検証に使わない。ローカル実AI評価も先に費用を連絡し、Viteの除去設定とフラグを明示的に変更する必要がある。その設定をCIへ持ち込まない。

AI Gatewayは `skipCache:true` / `collectLog:false` / `retries:{maxAttempts:1}` を毎回指定する。アプリログには音声・文字起こし・ToDo名・draft・Cookieを出さない。GatewayのSpend Limitsは結果整合性で、音声時間課金の集計も保証されない。D1カウンターは同時実行も直列に予約し、欠損やDB障害時はAIを呼ばない。

Gateway資源作成・本番権限・ASR/LLM実応答shape・認識精度・速度・実料金は自動テストの対象外。APIの公開型に従って実装しているが、初回の有料になり得る疎通で別途確認する。

## 検証とiPhone実機受け入れ

`bun run test:local` は使い捨てD1でbuild/型/lint/境界/UI/HTTP/認証/DB/ブラウザーを検証する。音声テストは以下の分担とし、fixture成功を実AI・実機成功とは扱わない。

- `audio.test.ts` / `capture.test.ts` / `worklet.test.ts`: 16kHz変換、無音で継続・2分上限・停止時の末尾PCM flushと応答期限、開始応答前の準備維持と期限・重複開始時のPCM保持・sample数不一致の送信抑止、35秒の録音の先頭/途中/末尾保持、許可/音声準備のタイムアウトと1回の復旧、閉じた後のマイク許可・module完了の破棄、live trackでの初期化と終了時の解放。
- `VoiceSession.test.ts`: 開くだけでは録音しない、文字のみの送信、停止/停止して送信の違いと二重送信防止、停止応答前の送信準備状態と前の結果の解除、追記・上限超過保持、二度目起動/初期化の期限、未送信破棄、遅い応答・取消・draft。
- `encode.test.ts`: PCMの所有権転送、変換の期限・エラー・終了時のWorker破棄。Sessionでは描画待ちを挟まずに変換や文字の送信を開始し、閉じた後の変換結果を破棄することを確認する。実ブラウザーでは変換へ1秒のCPU負荷を入れ、ASR要求前に送信ボタンの待機表示が複数frameで観測されることを確認する。ASR/LLM応答の遅延を使った代用検証にはしない。
- `assist.test.ts`: 実D1の追加/一覧/聞き返し/無変更、strict契約、所属固定・失効・中断。
- `assist-budget.test.ts`: 同時予約・60秒窓・UTC日替わり・累計上限・欠損時停止。
- `assist-ai.test.ts`: 指定モデル・Turboのbase64/日本語指定・GemmaのJSON schema/thinking無効化・入力/出力形式・再試行なし・異常応答の拒否。
- `assist-transport.test.ts`: HTTP境界・頻度制限・Gatewayオプション・実D1保存・通知・内容を含まないログ。
- Playwright: 明示的な端末API/HTTP fixtureで手動録音・無音で継続・停止/停止して送信・文字だけの入力、反復録音/閉じる/再起動、320px幅/480px高の入力欄と操作、focus、フォーム競合、無効時の実HTTP入口を確認。加えて合成トーンを実AudioContext/AudioWorkletへ通し、送信WAVに先頭/途中/末尾の信号が順に残り、返された日本語全文が入力欄と送信要求まで保持されることを確認する。ASR応答はfixtureで、認識精度の証明ではない。ChromiumのiPhone画面サイズであり、Safari実機ではない。

最初の対象端末は **iPhone Safari／ホーム画面アプリ**。HTTPSと有効化済みの検証環境で、ユーザー本人がマイクを許可して行う。

1. 画面を開くだけで許可が出ないこと、録音開始時の初回許可・拒否・許可し直しを確認。
   許可ダイアログを20秒以上保留し、遅れて許可しても録音し続けないこと、閉じて再度開くと起動できることを確認する。初期化の中断後も、準備のまま放置されず復旧または終了案内へ進むことを確認する。
2. 録音を開始→「買い物に牛乳を追加して」→無音でも録音が続く→停止→文字起こしを確認/修正→送信→文字での返事→再録音、をSafari/PWAで複数往復。別の録音では「停止して送信」で1回だけ実行されることを確認。送信前はDBが変わらず、送信後の件数が実結果と一致することを確認。閉じて2回目/3回目も録音できることを確認。
3. カテゴリーの聞き返し、複数品の全件追加、編集依頼・無音のみ・2分上限で意図しない操作がないこと、同名ToDoの完了・削除、名前/カテゴリー検索、推測された追加先が正しいことを確認。
4. 換気扇など生活音、画面ロック/別アプリ/タブ移動・電話等の中断から勝手に再開しないことを確認。
5. 閉じる/ログアウト/所属変更でマイク表示が消えること、保存直後の通信断で重複送信しないこと、他端末への反映を確認。
6. 合成の20〜30発話で誤追加・認識精度・返事までの所要時間を記録。初期目標は誤追加0、通常指示成功95%以上、中央値3秒/p95 6秒以内。現時点の達成値ではない。

ソフトウェアキーボードを開いても入力欄・停止・送信へ到達できること、文字の追記・修正と画面終了時の破棄を実機で確認する。
