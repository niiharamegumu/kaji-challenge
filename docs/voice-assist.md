# 常駐音声アシスト

## 利用範囲

下部のガラス調の波形ボタンを押すと、現在の画面が聞き取りモードになる。起動ボタンは「その他」と同じ62pxとガラス背景を使う。発話終了後はマイクを解放して文字起こしだけを行い、編集可能な確認欄に表示する。ユーザーが「送信」を押して初めて、表示された文字をLLMが解釈してToDoの追加・確認を行う。発話終了や文字起こし完了だけでは操作しない。

送信時に端末内の日本語音声で「確認します」と伝え、結果を短く読み上げる。続ける場合は「もう一度録音する」で明示的に次の録音を開始する。確認中の「録音し直す」は未送信の文字を置き換える。画面の非表示、ページ移動、ログアウト、所属変更、発話前の無音待機では終了する。閉じた後や画面復帰だけで再開せず、会話と文字起こしは閉じると破棄する。

| 発話 | 動作 |
| --- | --- |
| 買い物に牛乳を追加して | 実在する「買い物」に1件追加 |
| 牛乳を追加して | カテゴリーがある場合は聞き返す。登録カテゴリーがなければ未分類 |
| 買い物（聞き返しへの返事） | 未確定の名前と組み合わせて検証・追加 |
| やることを教えて／買い物リストを教えて | 実データの件数と先頭2件を読み上げ、最大20件を表示 |
| 牛乳と卵を追加して | 複数品をまとめて追加。カテゴリー不明なら全件保留して聞き返す |
| やめて（聞き返し中） | 未確定の内容を破棄 |

完了・編集・削除・期日・リマインダー・日間/週間タスク・汎用会話は対象外。音声解釈は確率的なので、実AIでの誤認識評価が必要。名前とカテゴリーを推測して補完せず、候補不正や曖昧なカテゴリーでは保存しない。

既存の「追加」フォームと同時に起動しない。カレンダーは「その他」へ移動し、URL `/calendar`、ホームのリマインダー、予定データ、Cronは維持する。`/assist` は作らない。

## 実装と境界

- `features/assist` がマイク・VAD・読み上げ・直近の会話・ダイアログを管理する。RootLayoutは本人/所属をkeyにして状態を破棄する。native dialogで背面操作とフォーカス移動を制限する。
- AudioWorkletで取得した実sampleRateのPCMをmono/16kHz/16bit WAVに変換する。最大30秒、約1秒の末尾無音、発話前20秒の無音で停止する。短いクリック音とデジタル無音は送らず、30秒で切れた発話も切り落としたまま実行しない。文字起こしと確認文は最大2,000文字。生活音向けの閾値調整は実機評価が必要。
- マイク初期化中はlive trackを維持して音声セッションを安定させ、聞き取り前のPCMは破棄する。発話終了時にtracksとAudioContextを停止し、ASR・確認・LLM・読み上げの間はマイクを保持しない。終了時はタイマー・HTTP・読み上げも破棄し、遅い許可や応答を世代番号で無効化する。
- 起動時のマイク許可待ちは20秒、AudioContext再開とAudioWorklet準備は1回5秒で打ち切る。音声処理の準備に失敗した場合は、取得済みのマイクを使い、AudioContextを1回だけ作り直す。許可拒否・許可待ちの期限超過ではマイクを再要求しない。復旧できなければ録音を解放し、閉じてもう一度開く案内を表示する。終了後に許可・module読み込みが完了しても録音を再開しない。
- 起動時の挨拶をなくし、マイク初期化と読み上げを並行しない。起動全体の30秒期限を設け、待ち続けず再録音または終了に進める。聞き取り中の中断、画面非表示・ページ離脱では停止する。マイク要求は明示的な録音開始につき1回で、復旧時は再要求しない。
- マイク許可の保持はOS/ブラウザー管理であり、PWAの終了後も許可を保存することをアプリから強制できない。許可されたように見せるlocalStorageフラグや、閉じた後のマイク保持は使わない。毎回確認される場合は端末・ブラウザーのマイク設定を確認する。Safariとホーム画面PWAの権限状態はそれぞれ実機で確かめる（[getUserMediaの許可仕様](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)）。
- `SpeechSynthesis` は `localService` がtrueの日本語音声だけを選ぶ。`voiceschanged` で候補の遅延読み込みに対応する。音声がない/再生に失敗した場合は録音を停止し、短い理由を表示する。保存済みの結果は画面に残す。送信ボタンのユーザー操作中に短い確認音声を始め、iOSの読み上げ開始条件を満たしてから非同期の結果を読む。読み上げの途中でマイクを再開しない。遠隔音声に黙って切り替えない。
- `POST /api/assist/transcribe` は音声とexpectedTeamIdだけを受け、Whisperの文字起こしだけを返す。本文は2 MiB以下、実WAVの長さ・形式・無音を検証する。`POST /api/assist/turn` はユーザーが確認した文字とexpectedTeamId・任意のdraftだけを受け、Gemmaの解釈と認可済み操作を実行する。こちらの本文上限は1 MiB。実行入口は音声だけの旧入力を拒否する。
- 両入口はstrict Zod契約、same-origin、Better Auth、DB上のセッション・所属、本人ごとの頻度制限を通す。AI待機前に所属を固定し、各待機後と業務操作前後にも再検査する。ASRも送信もそれぞれ予算を予約し、未送信の文字起こしからLLMやDB更新を呼ばない。
- `AssistAi` portの実装だけがWorkers AIに依存する。Whisper large v3 turboへbase64 WAVと`language:"ja"`・`task:"transcribe"`を渡して日本語文字起こし、Gemma 4 26B A4Bで限定intentのJSONを取得する。Gemmaはthinkingを無効化し、名前付きJSON schemaで出力を指定する。未知キー・任意ID・対象外操作・途切れたJSONは拒否する。ToDo一覧をLLMへ送らない。
- 追加は認可済みRepositoryのatomic複数保存、一覧は既存 `executeOperation` を使う。全項目を検証してから保存し、一部だけ追加しない。JSON出力とdraftの上限は50項目。50の異なるカテゴリーでもD1のbind数上限を越えないよう、カテゴリー参照をJSON配列でまとめてSQL検査する。返事は保存/取得結果から定型生成する。migration `0010_assist_usage.sql` は利用量カウンターのみを追加する。
- 未確定draftは最大2分、名前/カテゴリー/不足情報/期限のみ。本人や権限の根拠にせず、毎回再検証する。会話はパネル内メモリーのみで、閉じると破棄する。
- 更新は自動再送しない。中断や応答不明では既に保存されている可能性を表示して一覧を再取得する。処理中に閉じた場合は通常画面の通知で保存済みの可能性を伝える。成功時は既存ToDo queryとRealtimeで反映する。

## 設定・費用

**実推論と配備は既定で無効。作業担当者は、有料になり得る実AI試験・Cloudflareへの変更の前に、目的・回数/費用の見込みをユーザーへ連絡する。** この初版の自動検証は実AIを呼ばない。

| 設定 | 初期値・意味 |
| --- | --- |
| `ASSIST_ENABLED` | `false`。有効化は明示的に `true`。AIより前に停止する |
| `ASSIST_GATEWAY_ID` | `kaji-voice`。AlchemyとWranglerで一致 |
| `AI` | 既存アプリWorkerのみ。Viteのdev/build/previewではbindingを除去し、remoteBindingsもfalse |
| `ASSIST_LIMITER` | 本人ごと12要求/60秒。ASR・送信・聞き返しをそれぞれ数える。分散環境での厳密な全世界カウンターではない |
| Gateway | ログなし、キャッシュなし、24推論/60秒。ASR・送信はそれぞれ最大1推論 |
| Gateway認証 | Alchemyで `authentication:true` を明示。未認証HTTPを拒否し、同一アカウントのWorker bindingは自動認証する。特定Workerだけのallowlistではなく、有効なAPI token経由も許可される |
| Spend limits | $1/1日・$5/30日。`limit` は米ドル単位で `1` / `5` を指定する。厳密な請求上限ではない |
| D1利用上限 | アプリ全体12要求/60秒、50要求/UTC日、試用累計500要求。ASRと送信は別々に消費する。AIより前に条件付きUPDATEで予約。失敗・中断も消費、日付変更や再配備で累計を戻さない |
| 推論上限 | 音声30秒、文字2,000文字、解釈入力JSON 65,536 UTF-8 bytes、出力8,192 tokens/65,536 bytes。別モデルへの自動切替なし |
| 会話時間 | 起動から3分で終了。再開には本人のタップが必要 |

本番はGitHub Environmentの `ASSIST_ENABLED` をCDが読む。Alchemyは有効時に専用Gatewayを宣言し、無効化時はretainして既存資源を削除しない。モデル名・Gateway・RateLimitはMCP Workerに追加しない。配備はこの実装だけでは行わない。

Gateway認証の設定変更は次の有効状態でのAlchemy配備で反映する。手動でスイッチだけ変更しても、IaCが未変更なら次回配備で戻るため、`authentication:true` を正本とする。AI Binding経由では追加のGateway tokenやブラウザー側の秘密情報は不要（[Cloudflare公式](https://developers.cloudflare.com/ai-gateway/configuration/authentication/)）。本番の反映確認と実推論の疎通は別の検証であり、ローカルテスト成功だけで完了扱いにしない。

ローカルのWrangler宣言は生成型のためにAIを含むが、通常の起動は `bun run dev` / `bun run preview` を使い、ViteでAIを除去する。`wrangler dev` の直接実行はリモートAIへ接続し得るので通常検証に使わない。ローカル実AI評価も先に費用を連絡し、Viteの除去設定とフラグを明示的に変更する必要がある。その設定をCIへ持ち込まない。

AI Gatewayは `skipCache:true` / `collectLog:false` / `retries:{maxAttempts:1}` を毎回指定する。アプリログには音声・文字起こし・ToDo名・draft・Cookieを出さない。GatewayのSpend Limitsは結果整合性で、音声時間課金の集計も保証されない。D1カウンターは同時実行も直列に予約し、欠損やDB障害時はAIを呼ばない。

Gateway資源作成・本番権限・ASR/LLM実応答shape・認識精度・速度・実料金は自動テストの対象外。APIの公開型に従って実装しているが、初回の有料になり得る疎通で別途確認する。

## 検証とiPhone実機受け入れ

`bun run test:local` は使い捨てD1でbuild/型/lint/境界/UI/HTTP/認証/DB/ブラウザーを検証する。音声テストは以下の分担とし、fixture成功を実AI・実機成功とは扱わない。

- `audio.test.ts` / `capture.test.ts`: 16kHz変換、語頭保持、無音・上限、許可/音声準備のタイムアウトと1回の復旧、閉じた後のマイク許可・module完了の破棄、live trackでの初期化と終了時の解放。
- `VoiceSession.test.ts`: ASRだけでは実行しない、確認文の編集・明示送信・二重送信防止、二度目起動/起動全体の期限、未送信破棄、保留応答・取消・再生失敗、draft。
- `assist.test.ts`: 実D1の追加/一覧/聞き返し/無変更、strict契約、所属固定・失効・中断。
- `assist-budget.test.ts`: 同時予約・60秒窓・UTC日替わり・累計上限・欠損時停止。
- `assist-ai.test.ts`: 指定モデル・Turboのbase64/日本語指定・GemmaのJSON schema/thinking無効化・入力/出力形式・再試行なし・異常応答の拒否。
- `assist-transport.test.ts`: HTTP境界・頻度制限・Gatewayオプション・実D1保存・通知・内容を含まないログ。
- Playwright: 明示的な端末API/HTTP fixtureで確認・編集・送信、反復録音/閉じる/再起動、62pxのガラス調ナビ、focus、フォーム競合、無効時の実HTTP入口を確認。ChromiumのiPhone画面サイズであり、Safari実機ではない。

最初の対象端末は **iPhone Safari／ホーム画面アプリ**。HTTPSと有効化済みの検証環境で、ユーザー本人がマイクを許可して行う。

1. 初回許可・拒否・許可し直し、日本語ローカル音声の有無、遅延読み込みを確認。
   許可ダイアログを20秒以上保留し、遅れて許可しても録音し続けないこと、閉じて再度開くと起動できることを確認する。初期化や読み上げによる中断後も、準備のまま放置されず復旧または終了案内へ進むことを確認する。
2. 「買い物に牛乳を追加して」→文字起こしを確認/修正→送信→短い返事→明示的に再録音→「買い物リストを教えて」をSafari/PWAで複数往復。送信前はDBが変わらず、送信後の件数が実結果と一致することを確認。閉じて2回目/3回目も録音できることを確認。
3. カテゴリーの聞き返し、複数品の全件追加、完了依頼・無音・30秒超で意図しない追加がないことを確認。
4. 返事の回り込み、換気扇など生活音、画面ロック/別アプリ/タブ移動・電話等の中断から勝手に再開しないことを確認。
5. 閉じる/ログアウト/所属変更でマイク表示が消えること、保存直後の通信断で重複送信しないこと、他端末への反映を確認。
6. 合成の20〜30発話で誤追加・認識精度・返事までの所要時間を記録。初期目標は誤追加0、通常指示成功95%以上、中央値3秒/p95 6秒以内。現時点の達成値ではない。

実機で非同期の自動読み上げが成立しなければ、文字表示だけで完了とせず、音声方式・起動動作を再調整する。

## 料金調査（2026-10-25）

- [Workers AI料金](https://developers.cloudflare.com/workers-ai/platform/pricing/): 10,000 neurons/日が無料。Paidは超過分$0.011/1,000 neurons。既存アカウントの他用途と共有する。
- [Whisper large v3 turbo](https://developers.cloudflare.com/workers-ai/models/whisper-large-v3-turbo/): $0.000513/音声分。
- [Gemma 4 26B A4B](https://developers.cloudflare.com/workers-ai/models/gemma-4-26b-a4b-it/): 入力$0.10、出力$0.30/各100万tokens。ユーザー指定により採用。
- 音声30秒のASRは約$0.000257。Gemmaの出力が上限8,192 tokensに達した場合、その出力分は約$0.00246で入力分が別途加わる。上限緩和により1回の最大費用は増え得る。入力byte上限はtoken計測ではなく、内部chat template・課金丸め・Workers/D1等も別。ASRと送信を別予約するため、試用500要求を500回の音声操作と換算しない。
- [Gateway金額上限](https://developers.cloudflare.com/ai-gateway/features/spend-limits/)は事後集計・結果整合。[費用集計](https://developers.cloudflare.com/ai-gateway/observability/costs/)はtoken情報を返すendpointが対象。アカウント全体の請求を保証する上限ではない。
- 上限に達したらToDo画面を案内し、自動再試行しない。試用累計を増やす場合は料金・利用実績を確認して明示的に変更する。
