# 共有ページ

`/pages` にチーム共通の文書を保存する。通常の家事ToDo・実績・減点・月次締めとは独立し、ページのチェック項目は本文の一部としてのみ扱う。

## 保存と認可

専用の `shared_pages` D1テーブルにタイトルとBlockNoteのJSONを保存する。文書は `format: "blocknote"`、`schemaVersion: 1`、`blocks` を持つ。Markdownへの変換を保存経路に入れず、将来の形式変更はschemaVersionに応じた明示的な移行として扱う。

段落・見出し・箇条書き・番号付きリスト・チェックリストと基本の文字装飾・リンクに制限する。文書サイズ・ブロック数・階層・リンクschemeを契約で検証する。画像アップロード、AI、複数カラム、リアルタイム共同編集は含めない。

全操作は既存Server Function入口で認証・Originを確認し、Applicationで所属を固定する。Repositoryの各SQLにも現在の本人・認証セッション・所属と対象ページのteamIdを含める。他チームのIDと不存在のIDはいずれも404。本文をログへ出さない。

新規作成はフォームごとにUUIDを発行し、同じフォームの手動再試行で再利用する。D1はチーム・本人・要求IDに対応する作成記録とページを同じbatchで登録する。保存後に応答が途切れても、元のページが作成時のままで入力が一致すれば同じページを返す。入力や版が異なる場合、または削除済みの場合は409で入力を保持する。ページ削除後も要求IDとページIDの記録を保持し、チーム・ユーザー削除時に消去する。旧クライアントの要求IDなしの作成も受け付ける。

## 編集権と版

初期版はユーザー単位の排他とする。閲覧は編集権を取得せず、「編集する」で90秒のリースを取得する。編集権の保存項目は `lease_user_id` と `lease_expires_at` の2つだけ。期限とチーム所属をD1の実時計で判定した単一の条件付きUPDATEにより、異なるユーザーの同時取得は一人だけが成功する。本人は別タブ・別端末からも同じ編集権を利用できる。

取得時には同じSQLのRETURNINGで最新の本文を返す。保存・リース更新・解放・削除には編集ユーザーの一致、現在の呼出元の有効な認証セッション・チーム所属・期限を要求する。編集者IDはリクエスト本文から受け取らず、認証結果から決める。別ユーザーへ引き継いだ後は、元のユーザーによる保存や解放を拒否する。編集権にログインセッションIDやタブIDを保存しないため、ログアウト等で解除要求が届かなかった場合は期限で解放する。

本文の `version` は編集権とは別の版管理として残す。保存と削除で現在の版を比較し、古い内容を元にした書き込みを拒否する。既存家事APIへrevisionやETagを戻す変更ではない。

同じユーザーの複数画面は編集権を共有するため、片方の終了・離脱がもう片方の編集権も解放する。同じユーザーが再取得した後の古い画面からの更新・解放を区別する仕組みも持たない。この範囲の干渉防止はユーザーの指定により初期版の対象外とする。版比較は古い本文の保存を防ぐが、画面単位の排他を代替しない。

リース更新は操作中の画面のみが行う。通信失敗・期限切れ・放置時は保存を止め、入力保持とコピーを提供する。保存失敗を契機に古い入力を無条件で再送しない。応答が不明でも実際の保存が成功している場合があるため、版不一致では最新の内容を確認する。

編集操作が続く間は25秒ごとにリースを更新し、操作が5分ない場合は編集を停止する。本文は日本語変換の終了と800msの入力停止を待って保存する。保存中の追加入力は次の保存へ残し、送信は1件ずつ行う。保存に失敗した後は自動再送せず、利用者の再試行を待つ。

## 通知

既存TeamRealtimeに `shared-pages` scopeを追加する。作成・保存・削除・編集権の取得/解放を通知し、heartbeatのたびの配信はしない。通知の本文に文書は含めない。保存後の通知失敗は保存を取り消さない。再接続・フォーカス復帰時はD1から再取得する。未保存編集中の本文をQueryの再取得結果で置き換えない。

共同編集用DOは追加しない。将来の同時編集は、このJSON形式の移行と認可境界を維持した別の設計として検討する。

## UIとモバイル

PCは一覧と本文、スマホは一覧から本文へ遷移する。スマホ幅の本文・作成画面では非表示の一覧を取得・定期更新せず、PC幅に広げるか一覧に戻った時点で取得する。PCの本文画面ではアプリヘッダーを通常フローに置き、本文ツールバーだけを固定して長文スクロール時の重なりを防ぐ。スマホの本文画面では通常の大きいヘッダーとフローティングナビを省き、戻る・保存状態・編集終了を上部に集める。閲覧中のチェック操作は無効で、変更には編集権が必要。

追加・戻る・編集・編集終了・削除・コピー・ブロック追加の常設操作は、既存のToDoやカレンダーと同じ16pxのアイコンを使い、44px四方の操作領域を確保する。日本語の読み上げ名とツールチップを付け、保存状態・ブロック種別・削除確認・エラー復旧・未保存内容の破棄確認は文字で説明する。

編集時は、段落・見出し・箇条書き・番号付きリスト・チェック項目の左端に並び替えハンドルを表示する。チェック項目ではハンドル、チェックボックス、本文の順に並ぶ。ハンドルをドラッグするか、タップして上下の矢印を使うと、同じ階層内で順番を変更できる。親を移動すると、その子孫も順序・項目ID・書式・チェック状態を保って一緒に移動する。変更は本文と同じ経路で保存する。

本文は[BlockNoteの初期値と変更イベント](https://www.blocknotejs.org/docs/getting-started/editor-setup)で扱い、入力のたびにエディターへ文書を渡し直さない。画面はタイトル・保存状態など表示に必要な値だけを購読する。並び替えのハンドルは文字だけが変わった場合に読み上げ名を更新し、折り返し・幅の変化・ブロックの追加や移動があった場合に配置を測り直す。

閲覧中・本文の編集中は、文字を選択して必要な範囲だけコピーできる。タッチ端末では長押し、PCではドラッグで選択し、端末のコピー操作を使う。

編集中は一覧と本文ツールバーに、編集者の設定色と名前の頭文字のアイコンを表示する。既存のチームメンバーキャッシュを編集ユーザーIDで参照し、名前は読み上げとツールチップでも確認できる。メンバー情報の取得前や取得失敗時も、ページが持つ編集者名と標準色で表示する。新しい保存項目は追加しない。

BlockNote標準の日本語UIとモバイルFormatting Toolbar、`interactive-widget=resizes-content` を使う。アプリ全体の固定化が画面遷移後のナビ配置に影響しないよう、任意の `bn-scroll-container` は使用せず、既存画面と同じドキュメントスクロールを使う。スマホの本文・ツールバーは共通のcanvas背景とし、上の安全領域は固定ツールバーの内側で確保する。本文の最小高さには親の下の安全領域を重ねて計上しない。独自のキーボード処理や依存ソースへのパッチは追加しない。iPhone実機でのキーボード表示中のスクロールと一覧復帰時のナビ位置は別途確認が必要。未保存時の画面移動、ブラウザー離脱、ログアウトを確認する。ブラウザーの終了警告はOS/ブラウザーにより表示が保証されないため、保存済み表示を確認して終了する。

未保存確認は共通ConfirmModal、手動コピーの補助は共通FormSheet、削除確認は共通DeleteConfirmModalを使う。保存中の破棄を抑止し、コピー補助を閉じても未保存確認と入力を残す。削除はツールバーのアイコンから確認を開き、送信中の表示・二重操作抑止を行う。他の人が編集中なら削除操作も無効にする。通常の編集者表示は中立色、失効・保存失敗だけ警告色にする。コピー成功は設定画面と同様に短時間のチェック表示で知らせる。ブロック追加メニューは外側クリック・Escapeで閉じる。

既存ページは編集を開くと「変更なし」、入力後は「未保存」、更新リクエスト中は「保存中…」と表示する。「保存済み」は現在の入力がサーバーに保存されたことを示す。目のアイコンは「編集を終了」で、残っている変更があれば保存してから編集権を解放し、閲覧に戻る。新しいページは作成前に「未作成」と表示し、右上の＋で作成する。

未保存入力は同じタブのsessionStorageにも退避する。最初の変更は直ちに記録し、連続入力は250ms単位で最新の草稿を記録する。タブが隠れたとき、ページ離脱時、保存失敗時は保留分を直ちに反映する。ブラウザーの強制終了などでこれらの通知が届かなければ、最後の記録以降の入力は復旧できない。キーはユーザー・チーム・ページごとに分離し、認証切れや再読込後は同じ本人・チームで当該ページを開いたときに復旧を案内する。認証情報・送信キューは保存しない。復旧文書は読み取り専用で、コピーと最新内容の確認に使い、自動取得・自動保存を行わない。保存成功・明示的な破棄・削除で草稿を消す。storageが使用できない場合は画面を閉じる前のコピーを案内する。タブを閉じた後の復旧や他端末への未保存草稿の同期は保証しない。
